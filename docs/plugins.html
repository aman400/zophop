ZopHop Node Plugin SDK

Extend ZopHop with custom Triggers, Parsers, Logic Checks, or Delivery Actions without recompiling the main app. Distribute plugins as standalone APKs over AIDL IPC or bundle them in-process via Java ServiceLoader.

JitPack: com.github.aman400.zophop:plugin-api:v1.0.0 Offline .aar Assets AIDL API v1

1. Architecture & Discovery Lifecycle

UnifiedPluginRegistry merges built-in SPI modules (BuiltInPluginRegistry) and external APK services (ExternalPluginRegistry), deduplicating by typeId or (displayName + category).

  1. Intent Query: ZopHop queries PackageManager for dev.zophop.plugin.ACTION_NODE_SERVICE, skipping itself and user-disabled plugin packages.
  2. Manifest Exchange (5s timeout): ZopHop calls getPluginApiVersion() and getManifests() returning Parcelable NodePluginManifest descriptors.
  3. Credential Registration: CredentialSpecRegistry indexes any attached credentialSpec so users can create secrets in ZopHop's Encrypted Vault.
  4. Execution & Output Propagation (15s timeout): ExternalPluginExecutor injects Vault fields as _cred_<key> into inputContextJson, invokes executeNode(...), and writes returned outputDataMap keys back into ExecutionContext.

ConfigFieldSpec UI Primitives & CredentialSpec

  • ConfigFieldSpec.TextField(key, label, tooltip, placeholder, singleLine, minLines, isTestField, isSecret) — Set isSecret = true to mask sensitive fields.
  • ConfigFieldSpec.DropdownField(key, label, tooltip, options: List<Pair<String, String>>) — Dropdown selector storing option keys.
  • ConfigFieldSpec.CodeTemplateField(key, label, tooltip, minLines, singleLine, maxLength) — Multi-line template editor with automatic ${variable} quick-insert chips.
  • CredentialSpec(typeId, displayName, description, fields) — Registers custom Vault forms. CredentialType.isCompatibleWith(...) also permits generic BEARER_TOKEN as a fallback.
  • core:model helpers: WorkflowNode, WorkflowConnection, AppJson, parseJsonObjectSafe(...), and null-safe optString / optBoolean / optInt extensions.

5. Credential Injection, Context & Structured Logs

  1. Vault Injection (_cred_*): When a user attaches a Vault credential to your node, ZopHop copies every key-value pair in credential.dataMap into inputContextJson prefixed with _cred_ (e.g., botToken → _cred_botToken, generic Bearer → _cred_token).
  2. Context Interpolation: Reconstruct ExecutionContext from inputContextJson and call context.interpolate(template) to expand ${var} and {var} placeholders.
  3. Redacted Logs: Use ExecutionLogFormatter.formatHeadersBlock(...) and ExecutionLogFormatter.buildStructuredLog(...) so ZopHop's Complete Execution Log modal displays collapsible sections with Authorization, tokens, and cookies automatically masked.

6. Security, Caller Verification & Permissions

Because your plugin Service uses android:exported="true", always verify Binder.getCallingUid() inside executeNode(...) so third-party apps cannot abuse your service:

Caller Verificationprivate fun isTrustedZopHopCaller(): Boolean { val callingUid = Binder.getCallingUid() if (callingUid == Process.myUid()) return true val packages = packageManager.getPackagesForUid(callingUid) ?: return false return packages.any { it == "dev.zophop" || it == "dev.zophop.debug" } // For production release plugins, also verify SigningInfo SHA-256 or checkSignatures(). }

8. Testing & Debugging Your Plugin

  1. Install both APKs (./gradlew assembleDebug && adb install -r app/build/outputs/apk/debug/app-debug.apk).
  2. Open ZopHop → Settings & Permissions → Installed Node Plugins to confirm your plugin is discovered, and open Vault → Add Credential to confirm SLACK_AUTH appears.
  3. Run a Test Run inside Pipeline Builder and inspect View Full Log to verify Authorization: Bearer *** redaction and slack_ts / slack_channel outputs.
  4. Unit test SlackActionExecutor(mockClient) using OkHttp MockWebServer on JVM without needing an emulator.
