Signed Releases, External APKs & JitPack SDK

Every release tag triggers .github/workflows/release.yml to test, sign, and attach APKs and SDK AARs to GitHub Releases. Public Maven artifacts are served automatically from release tags via JitPack.

1. Local Signed Build Generation

Step A: Generate a Keystore (One-Time Setup)

Shellkeytool -genkey -v -keystore release.keystore \ -alias zophop_key \ -keyalg RSA \ -keysize 2048 \ -validity 10000

Step B: Build Release APKs & Plugin SDK AARs

GradleKEYSTORE_FILE=release.keystore \ KEYSTORE_PASSWORD=your_password \ KEY_ALIAS=zophop_key \ KEY_PASSWORD=your_password \ ./gradlew assembleRelease :core:plugin-api:assembleRelease :core:model:assembleRelease

Generated outputs:

Build Outputsapp/build/outputs/apk/release/ZopHop-v1.0.0.apk external/telegram/build/outputs/apk/release/ZopHop-Telegram-Plugin-v1.0.0.apk external/smtp/build/outputs/apk/release/ZopHop-SMTP-Plugin-v1.0.0.apk core/plugin-api/build/outputs/aar/plugin-api-release.aar core/model/build/outputs/aar/model-release.aar

2. Automated GitHub Release & JitPack Distribution

Step A: Optional Signing Secrets

To sign ZopHop-v1.0.0.apk, ZopHop-Telegram-Plugin-v1.0.0.apk, and ZopHop-SMTP-Plugin-v1.0.0.apk with your production keystore, Base64-encode release.keystore and add these Repository Secrets under Settings → Secrets and variables → Actions:

Shellbase64 -i release.keystore -o keystore_base64.txt
  • KEYSTORE_BASE64 — Contents of keystore_base64.txt
  • KEYSTORE_PASSWORD — Keystore password
  • KEY_ALIAS — Keystore alias (e.g., zophop_key)
  • KEY_PASSWORD — Key password
ℹ️
No extra secrets or environment variables are needed for GitHub Releases — the workflow automatically uses the built-in GITHUB_TOKEN (contents: write).

Step B: Sync Docs & Push Release Tag

Git Tag./gradlew syncVersion VERSION=$(grep -E '^ZOPHOP_VERSION=' gradle.properties | head -n 1 | cut -d'=' -f2- | tr -d '[:space:]') VERSION="${VERSION:-1.0.0}" git tag -a "v$VERSION" -m "ZopHop v$VERSION Release" git push origin "v$VERSION"

GitHub Actions automatically runs ./gradlew test --stacktrace, builds & signs all APKs/AARs, and attaches them to a GitHub Release. JitPack then builds and serves com.github.aman400.zophop:plugin-api and com.github.aman400.zophop:core-model publicly from the release tag.

3. Public SDK Distribution via JitPack

jitpack.yml automatically builds and publishes :core:model and :core:plugin-api whenever a tag is requested on https://jitpack.io. To verify the JitPack publication locally in ~/.m2:

Local JitPack Verification./gradlew -Pjitpack=true \ :core:model:publishReleasePublicationToMavenLocal \ :core:plugin-api:publishReleasePublicationToMavenLocal \ --stacktrace

External plugin authors can depend publicly without any authentication token (implementation("com.github.aman400.zophop:plugin-api:v1.0.0")) or use offline .aar assets from GitHub Releases — see the Plugin SDK Guide.
